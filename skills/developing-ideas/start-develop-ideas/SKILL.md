# Start Develop Ideas

## Start with the tracker

Open and update `workflow-tracker.md` before other work. Record Criterion B, the current criterion, the question that brought the work here, the developing-ideas document, the target artifact, and the likely next move.

Read `AGENTS.md`, the approved Design Brief and inquiry evidence, `GLOSSARY.md`, the project template, the current developing-ideas document, and the project sources relevant to the decision.

## Follow the default direction

Criterion B has four callable criterion skills:

1. **B1 — Develop design specifications:** `$develop-design-specifications`
2. **B2 — Develop feasible ideas:** `$develop-feasible-ideas`
3. **B3 — Present and justify the chosen design:** `$present-and-justify-the-chosen-design`
4. **B4 — Develop planning drawings and diagrams:** `$develop-planning-drawings-and-diagrams`

Start new Criterion B work with B1, then move through B2, B3, and B4. This is the opinionated default direction.

Follow the fog of war with the human. Design specifications and ideas may change each other. A prototype may expose a missing inquiry question. Planning documents may reveal that the chosen design needs another comparison. Move in any direction when the current question belongs elsewhere, following the movement rules in `AGENTS.md`.

## Diverge before converging

Use B1 to establish what the solution must achieve before judging ideas.

Use B2 to develop meaningfully different solution shapes. Avoid presenting one preferred idea with cosmetic variants. Ground each idea in the Design Brief, project evidence, prior art, and relevant technical sources. Use a focused prototype when direct evidence is needed to judge an idea.

Use B3 to compare the ideas against the design specifications. Lead with an evidence-backed recommendation and explain its limits. Choosing the design is a human decision. Record the chosen shape only after the human has selected or approved it.

Use B4 to make the chosen design precise enough to create. Select the drawings, diagrams, models, contracts, and other planning documents that fit the work. Complete the Spec by synthesizing settled decisions rather than restarting the interview.

## Coordinate the work

Invoke only the criterion skill needed for the current question. Give it the Design Brief, developing-ideas document, tracker position, relevant evidence, settled language, and any approved prototype results.

Reuse the subagent permission recorded under `AGENTS.md`. Fan out independent design explorations, targeted technical research, or review lenses when parallel work will widen the search or preserve context. Keep each assignment independent and require concise results with sources. Bring comparisons and decisions back to the main collaboration.

Build shared language throughout. Update `GLOSSARY.md` when a solution term settles. Create a decision record only for a choice that is difficult to reverse, surprising without context, and based on a real trade-off.

Each criterion skill updates its section of the developing-ideas document and reports what it established, the supporting evidence and uncertainty, remaining questions, and the recommended next move. Record the result in `workflow-tracker.md`.

## Complete Criterion B

Criterion B is complete when B1 through B4 are settled, one coherent design has been chosen and justified, the planning documents describe what creation requires, the Spec contains no blocking design decision, and the human approves it.

Use `$start-evaluate` with D1 and D2 when the Spec needs an independent evidence-based review. Return findings to the criterion that owns them.

Recommend `$start-create-solution` when turning the approved Spec into a logical implementation plan and tickets is the next useful work.
